Source
Swissdox archive query via LCP
The Swissdox platform (University of Zurich) provides licensed access to Swiss press archives covering print and online editions from the 1990s onwards. Queries are written in LCP (Linguistic Corpus Platform) syntax — a domain-specific language for searching tokenised, linguistically annotated corpora.

Articles were matched when any segment contained one of the target token forms: AI, IA, GenAI, LLM, or Chatbot. Article-level metadata (headline, date, source code, URL) was extracted via the byYear analysis block.
# LCP query — search AI-related forms across all segments Article a Segment@a s Token@s t1 OR form = "AI" form = "IA" form = "GenAI" form = "LLM" form = "Chatbot" # Extract article metadata aggregated by year byYear => analysis attributes a.head a.subhead a.pubdate a.source a.articleURL functions frequency

Export & cleaning
Result processing with Pandas
Query results arrive as tab-separated values from the LCP API. Because a single article can match multiple token forms (e.g. an article containing both AI and LLM appears twice in the raw export), the first processing step is deduplication on articleURL. Dates are normalised to ISO 8601. Rows with unparseable dates are dropped. The cleaned file is exported as swiss_ai_discourse_articles_de.csv.
# export_processor.ipynb import pandas as pd # Load raw TSV from LCP export df = pd.read_csv('query_result.tsv', sep='\t') print(f"Raw rows: {len(df):,}") # Deduplicate — same article can match multiple token forms df = df.drop_duplicates(subset=['articleURL']) print(f"After dedup: {len(df):,}") # Normalise date column to ISO 8601 df['pubdate'] = pd.to_datetime(df['pubdate'], errors='coerce') df = df.dropna(subset=['pubdate']) df['year'] = df['pubdate'].dt.year # Export df.to_csv('swiss_ai_discourse_articles_de.csv', index=False) print(f"Exported {len(df):,} articles — {df['source'].nunique()} outlets")

4
Analysis
LLM topic extraction & classification
A vLLM server runs Llama-3.1-8B-Instruct (4-bit quantised via unsloth) on a UZH GPU cluster. The llm_module.run pipeline classifies articles into user-defined topic categories, generates summaries, and optionally runs sentiment scoring. Sessions are managed via tmux to keep the vLLM server and the classification job independent.

The server must be started in a separate session before running classification. Always close the entrypoint with Ctrl+C after use to free GPU resources.
# 1. Start vLLM server in a dedicated tmux session tmux new -s vllm_server python -m vllm.entrypoints.openai.api_server \ --model unsloth/Meta-Llama-3.1-8B-Instruct-bnb-4bit \ --served-model-name llama \ --enable-lora \ --max-model-len 8192 \ --max-num-seqs 128 \ --trust-remote-code \ --port 8000 # Ctrl+B, D to detach and return to main session # 2. Run classification in a second session tmux new -s classify python -m llm_module.run \ --input_file data/cleaned.csv \ --output_file topics.json \ --categories "Regulation,Economy,Security,Society,Education" \ --mode all \ --sample 500 # Available modes: classify | summarize | verify | sentiment | all

Infrastructure
GPU server & file synchronisation
Processed files are synced between local workstation and the UZH GPU server using rsync. The rsync-exclude.txt file prevents large directories (.venv/, data/, __pycache__/) from being transferred. Initial upload uses scp.
# Upload project files to server (from local terminal) scp -r "<key_dir>" "<local_folder>" user@server.cl.uzh.ch:/home/user/project/ # Sync: server → local (incremental, skips existing) rsync -asv --ignore-existing \ --exclude-from rsync-exclude.txt \ -e "ssh -i <key>" \ user@server.cl.uzh.ch:/home/user/project/ ./ # Sync: local → server rsync -asv --ignore-existing \ --exclude-from rsync-exclude.txt \ -e "ssh -i <key>" \ ./ user@server.cl.uzh.ch:/home/user/project/

Serving
Flask REST API & this viewer
A lightweight Flask application (app.py) exposes the processed CSV as a REST API. It loads the CSV once at startup, maps Swissdox source codes to readable names and media types, and serves four endpoints. This viewer calls those endpoints from the browser.
# Install dependencies pip install flask pandas # Run locally python app.py # → http://localhost:5000 # ── API endpoints ────────────────────────────────────── # Full-text search with optional filters GET /api/articles?q=ChatGPT&year_from=2023&year_to=2024&sources=NZZ,SRF&limit=100 # All outlets with article counts (>5 articles) GET /api/sources # Corpus statistics (used for Overview header cards) GET /api/stats # Sources matching a specific query term GET /api/sources_for_query?q=Regulierung

Quick-start checklist

  • Place swiss_ai_discourse_articles_de.csv in the data/ folder
  • Place index.html, search.html, pipeline.html in the frontend/ folder
  • Run pip install flask pandas then python app.py
  • Open http://localhost:5000 — the search page loads live data automatically
  • For LLM analysis, start the vLLM server on the GPU cluster first (Step 4)
